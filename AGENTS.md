# Working in Simile

Simile is a Rust CLI workspace with strict source, compilation, application and presentation
boundaries.

## Structure

- `crates/simile-cli`: argument parsing, terminal rendering, logging and process exit behaviour.
- `crates/simile-artifact`: indexed runtime model and versioned `.similec` encoding/decoding.
- `crates/simile-compiler`: orchestration of all source adapters into one compiled service.
- `crates/simile-core`: application context, domain types and operations.
- `crates/simile-hcl`: HCL syntax parsing and semantic validation of behavior overlays.
- `crates/simile-learning`: sanitized exchange evidence and conservative learned-contract inference.
- `crates/simile-openapi`: JSON/YAML OpenAPI parsing and feature-line adapters.
- `crates/simile-smithy`: Smithy 2.0 IDL parsing and canonical-contract lowering.
- `crates/simile-typescript`: declarations-only semantic TypeScript parsing and lowering.
- `crates/simile-schema`: compiled JSON Schema graphs, validation and seeded synthesis.
- `crates/simile-runtime`: protocol-neutral execution primitives over loaded artifacts.
- `crates/simile-server`: HTTP routing, wire limits, listener lifecycle and runtime adaptation.
- `crates/simile-spec`: version-neutral API, behavior and compiled-service types.
- `crates/simile-cli/src/commands`: thin adapters from CLI arguments to core operations.
- `crates/simile-core/src/ops`: application behaviour, independent of Clap and terminal output.

## Change map

| Change | Location |
| --- | --- |
| Add or rename a flag | `crates/simile-cli/src/cli.rs` |
| Change the compiled artifact format | `crates/simile-artifact/` |
| Add a command adapter | `crates/simile-cli/src/commands/` |
| Implement behaviour | `crates/simile-core/src/ops/` |
| Change the canonical service model | `crates/simile-spec/` |
| Change OpenAPI ingestion | `crates/simile-openapi/` |
| Change Smithy ingestion | `crates/simile-smithy/` |
| Change semantic TypeScript ingestion | `crates/simile-typescript/` |
| Change body schema compilation, validation or synthesis | `crates/simile-schema/` |
| Change loaded-artifact execution | `crates/simile-runtime/` |
| Change HTTP routing or listener behavior | `crates/simile-server/` |
| Change the HCL language or validation | `crates/simile-hcl/` |
| Change proxy evidence or learned-contract inference | `crates/simile-learning/` |
| Change source coordination | `crates/simile-compiler/` |
| Add shared application state | `crates/simile-core/src/context.rs` |
| Change human or JSON rendering | `crates/simile-cli/src/terminal.rs` and the relevant command |
| Add end-to-end CLI coverage | `crates/simile-cli/tests/` |

Do not put domain behaviour in the Clap model or grow a command adapter into an operation. Do not
add a crate until a real compilation, ownership or reuse boundary exists.

OpenAPI, Smithy, or semantic TypeScript is the complete HTTP contract for one compilation. HCL is
an optional behavior overlay and must not redefine routes, request shapes or response shapes. Keep
source-specific syntax out of `simile-spec` and coordination policy out of the source adapters.

## Interface invariants

- stdout contains command results; stderr contains diagnostics and progress.
- JSON output is stable, serializable domain data and never contains ANSI escapes.
- Human colour follows `--color` and terminal capability.
- Broken stdout pipes are successful termination, not diagnostics.
- Never emit credentials, tokens or other secrets in output or tracing.
- Keep exit behaviour deliberate and covered by an end-to-end test.

## Verification

Run before handing work off:

```console
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --all-features --locked
cargo doc --workspace --all-features --no-deps --locked
cargo deny check
```

`.github/workflows/release.yml` is generated by `dist`; change `dist-workspace.toml` and run
`dist generate` rather than editing the workflow directly.
